# API Contract Testing

This document explains the contract testing setup for AuditOrbit, which ensures the backend API implementation matches its OpenAPI specification and the frontend TypeScript types stay in sync.

## Overview

The contract testing workflow consists of:

1. **Backend Contract Tests**: Validate API implementation against OpenAPI spec using Schemathesis
2. **Type Generation**: Generate TypeScript types from OpenAPI spec
3. **Frontend Type Check**: Ensure frontend code uses correct types

## Backend Contract Tests

### What is Contract Testing?

Contract testing validates that your API implementation matches its documented specification (OpenAPI/Swagger). It catches:

- Missing or incorrect response fields
- Wrong status codes
- Invalid data types
- Security issues (missing authentication)
- Performance problems

### Running Contract Tests Locally

**Prerequisites:**
```bash
# Install dev dependencies
cd backend
pip install -r requirements-dev.txt
```

**Start the backend server:**
```bash
cd backend
uvicorn app.presentation.main:app --reload
```

**Run contract tests:**
```bash
# Run all contract tests
cd backend
make test-contract

# Or directly with pytest
pytest -m contract app/tests/contract/

# Verbose output
make test-contract-verbose
```

### Test Configuration

Contract tests are configured in `backend/app/tests/contract/test_openapi_contract.py`:

- `max_examples=50`: Number of test cases generated per endpoint
- `deadline=None`: No timeout for hypothesis tests
- Validates all endpoints against OpenAPI schema
- Tests authentication requirements
- Checks response times (<2s)
- Validates content-type headers

### Adding Custom Contract Tests

```python
import pytest
import schemathesis

@pytest.mark.contract
def test_custom_endpoint():
    """Test specific endpoint behavior."""
    schema = schemathesis.from_uri("http://localhost:8000/openapi.json")
    
    # Your test logic here
```

## Frontend Type Generation

### Generating Types

The frontend uses `openapi-typescript` to generate TypeScript types from the backend's OpenAPI specification.

**Manual generation:**
```bash
cd frontend

# Make sure backend is running on http://localhost:8000
npm run api:gen

# Or specify a different backend URL
BACKEND_URL=http://localhost:8080 npm run api:gen
```

**Generated file:** `frontend/src/lib/api/types.gen.ts`

⚠️ **Do not edit this file manually!** It's auto-generated.

### Using Generated Types

```typescript
import { api } from '@/lib/api/client';
import type { paths } from '@/lib/api/types.gen';

// Type-safe API calls
const { data, error } = await api.GET('/api/v1/engagements');

// data is fully typed based on OpenAPI spec
if (data) {
  console.log(data.items); // TypeScript knows the structure
}
```

### Type-Safe API Wrapper Functions

Use the wrapper functions in `src/lib/api/endpoints.ts` for better ergonomics:

```typescript
import { submitAnnualPlan } from '@/lib/api/endpoints';

// Fully typed request and response
const result = await submitAnnualPlan({
  year: 2025,
  items: [/* ... */],
});

if (result.error) {
  console.error('Failed:', result.error);
} else {
  console.log('Success:', result.data);
}
```

## CI/CD Integration

### GitHub Actions Workflow

The `.github/workflows/contract-tests.yml` workflow:

1. **Setup**: Starts PostgreSQL, Python, Node.js
2. **Backend Tests**: 
   - Runs migrations
   - Starts FastAPI server
   - Executes contract tests with pytest
3. **Type Generation**:
   - Generates TypeScript types from OpenAPI
   - Uploads types as artifact
4. **Frontend Validation**:
   - Downloads generated types
   - Runs TypeScript compiler
   - Runs ESLint

### Workflow Triggers

- Push to `main`, `master`, or `develop` branches
- Pull requests to these branches
- Manual workflow dispatch

### Artifacts

The workflow produces:
- `openapi-types`: Generated TypeScript types
- `contract-test-results`: Test coverage and results

Download artifacts from the Actions tab to debug issues.

## Development Workflow

### When Backend Changes

1. **Update FastAPI routes/models**
2. **Run contract tests:**
   ```bash
   make test-contract
   ```
3. **Fix any schema mismatches**
4. **Regenerate frontend types:**
   ```bash
   cd ../frontend
   npm run api:gen
   ```
5. **Update frontend code** to use new types
6. **Commit both backend and frontend changes**

### When Frontend Needs New Endpoints

1. **Check if endpoint exists** in backend
2. **If not, implement in backend first**
3. **Generate types:**
   ```bash
   npm run api:gen
   ```
4. **Create wrapper function** in `endpoints.ts`
5. **Use in components**

### Type Checking

```bash
cd frontend

# Check types without building
npx tsc --noEmit

# Full lint
npm run lint
```

## Troubleshooting

### "Cannot find openapi-fetch"

Install dependencies:
```bash
cd frontend
npm install --legacy-peer-deps
```

### Contract Tests Failing

**Check OpenAPI schema:**
```bash
curl http://localhost:8000/openapi.json | jq
```

**Common issues:**
- Response doesn't match schema (missing/extra fields)
- Wrong status code returned
- Authentication not enforced
- Invalid data types

**Debug specific endpoint:**
```python
# In test file
@pytest.mark.contract
def test_specific_endpoint():
    schema = schemathesis.from_uri("http://localhost:8000/openapi.json")
    
    # Test only one endpoint
    for endpoint in schema.get_all_operations():
        if endpoint.path == "/api/v1/your-endpoint":
            case = endpoint.make_case()
            response = case.call()
            print(f"Response: {response.status_code}")
            print(f"Body: {response.text}")
            case.validate_response(response)
```

### Type Generation Fails

**Ensure backend is running:**
```bash
curl http://localhost:8000/health
```

**Check OpenAPI endpoint:**

## Best Practices

### Backend Development

1. **Document all endpoints** in OpenAPI (FastAPI does this automatically)
2. **Use Pydantic models** for request/response validation
3. **Add response_model** to all route decorators
4. **Run contract tests** before committing

```python
from fastapi import APIRouter
from pydantic import BaseModel

class ItemResponse(BaseModel):
    id: int
    name: str

router = APIRouter()

@router.get("/items/{item_id}", response_model=ItemResponse)
async def get_item(item_id: int):
    return ItemResponse(id=item_id, name="Example")
```

### Frontend Development

1. **Regenerate types** when backend changes
2. **Use wrapper functions** for common operations
3. **Handle errors** with the `safeCall` utility
4. **Don't modify** `types.gen.ts` manually

```typescript
// Good: Type-safe with error handling
const result = await submitAnnualPlan(data);
if (result.error) {
  toast.error(result.error.message);
} else {
  toast.success('Plan submitted!');
}

// Avoid: Direct API calls without wrapper
const response = await fetch('/api/...');
```

### Version Control

**Commit order:**
1. Backend changes (routes, models)
2. Run contract tests
3. Generate frontend types
4. Update frontend code
5. Commit everything together

**Don't commit:**
- `types.gen.ts` to main branch (regenerate in CI)
- Test artifacts (`htmlcov/`, `.coverage`)
