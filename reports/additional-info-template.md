# تقرير المعلومات الإضافية المطلوبة

## 1. حالة الكود الحالية

- [ ] تحديد الوحدات أو الملفات الأعلى تعقيدًا أو التي تسببت بمشاكل مزمنة.
- [ ] وصف الأجزاء الحساسة أو الهشة التي تحتاج حذرًا خاصًا.

## 2. حالة الاختبارات

- [ ] توثيق نسبة تغطية الاختبارات الحالية (وحدية/تكاملية).
- [ ] سرد الاختبارات الفاشلة باستمرار أو السيناريوهات غير المغطاة.

## 3. سير العمل الحالي

- [ ] أوامر التشغيل المحلي الحالية (scripts، make، docker).
- [ ] مهام CI/CD أو الأدوات الآلية المفعّلة حاليًا.
- [ ] أدوات الفحص (lint/format/security) المستخدمة أو الناقصة.

## 4. الاعتماديات والخدمات الخارجية

- [ ] قائمة الخدمات أو موفّري الطرف الثالث (هوية، بريد، تخزين ملفات، مراقبة...).
- [ ] التكوينات الحساسة أو المفاتيح التي يجب حمايتها وكيفية إدارتها.

## 5. خريطة قاعدة البيانات

- [ ] وصف مختصر للمخطط الحالي وعلاقات الجداول الحرجة.
- [ ] مشاكل الأداء المعروفة أو الفهارس المطلوبة.

## 6. سجل المشكلات والانقطاعات

- [ ] أبرز الأعطال السابقة أو الثغرات التي يجب تفاديها.
- [ ] متطلبات الامتثال أو التدقيق (audit/compliance) ذات الصلة.

## 7. وثائق وسياسات قائمة

- [ ] روابط أو مسارات للسياسات الداخلية (معايير التسمية، الأمن، مراجعات الكود).
- [ ] أي أدلة تشغيل أو إجراءات Incident Response.

## 8. الجداول الزمنية والأولويات

- [ ] مواعيد التسليم أو القيود الزمنية للمشروع.
- [ ] أجزاء لا يمكن تغييرها حاليًا أو يجب إنجازها أولًا.

## 9. ملاحظات إضافية

- [ ] أي تفاصيل أخرى يرى الفريق أنها مهمة لنجاح خطة إعادة الهيكلة.
