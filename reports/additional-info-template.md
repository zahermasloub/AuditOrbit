# تقرير المعلومات الإضافية المطلوبة

## 1. حالة الكود الحالية

- [x] تحديد الوحدات أو الملفات الأعلى تعقيدًا أو التي تسببت بمشاكل مزمنة: ملفات مجلد `api/app/presentation/routers/` (خصوصًا `engagements.py`, `checklists.py`, `reports.py`) تتجاوز 200 سطر وتستخدم SQL خام مع منطق أعمال متداخل؛ يوجد تكرار لمنطق مشابه داخل مجلد `backend/app` القديم وسلسلة سكربتات إجرائية في جذر `api/`.
- [x] وصف الأجزاء الحساسة أو الهشة التي تحتاج حذرًا خاصًا: وحدات المصادقة `auth.py`, مجلد `infrastructure/security/`, وطبقة RBAC الحالية تعتمد على استعلامات نصية مباشرة وتتعامل مع جداول `users/roles/user_roles`; ملف `users.py` ما زال على مخطط snake_case القديم وفقًا لـ `SCHEMA_MIGRATION.md` مما يزيد خطر الانكسار.

## 2. حالة الاختبارات

- [ ] توثيق نسبة تغطية الاختبارات الحالية (وحدية/تكاملية): لا توجد نسبة منشورة؛ خطوط GitHub Actions (`ci.yml`) تشغّل `pytest -q || true` من دون قياس تغطية أو فشل عند الإخفاق، ما يشير لعدم استقرار النتائج وعدم توفر تقرير رسمي.
- [ ] سرد الاختبارات الفاشلة باستمرار أو السيناريوهات غير المغطاة: لا تتوافر تقارير ثابتة، لكن غياب اختبارات مخصصة لتدفقات RBAC وعمليات `engagements/checklists/documents` واضح في مجلد `api/tests`; يجب التحقق من فشل متكرر عند التعامل مع login/authorization وفق تقارير مثل `ADMIN_USER_CREATION_DEBUG.md`.

## 3. سير العمل الحالي

- [x] أوامر التشغيل المحلي الحالية (scripts، make، docker): التشغيل يتم عبر `infra/docker-compose.yml` (`docker-compose up -d --build api` حاليًا يفشل) أو يدويًا بواسطة `api/start_api.ps1` و`frontend` مع `npm run dev`; لا يوجد هدف موحد مثل `make dev` على مستوى الجذر.
- [x] مهام CI/CD أو الأدوات الآلية المفعّلة حاليًا: توجد أعمال GitHub Actions (`auditorbit-ci`, `contract-tests`, `ui-perf-visual`) لكنها تعتمد على مسارات قديمة (`web/` بدل `frontend/`) وتسمح بفشل الاختبارات، ما يقلل الثقة بالنتائج.
- [ ] أدوات الفحص (lint/format/security) المستخدمة أو الناقصة: لا توجد إعدادات lint رسمية في `api`; ملف `backend/Makefile` يشير إلى `ruff`, `mypy`, `black` لكن هذه الأدوات غير مدمجة مع مجلد `api/`; لا وجود لـ import-linter أو أدوات فحص أمنية.

## 4. الاعتماديات والخدمات الخارجية

- [x] قائمة الخدمات أو موفّري الطرف الثالث (هوية، بريد، تخزين ملفات، مراقبة...): البيئة تعتمد على PostgreSQL، Redis، MinIO (S3 متوافق) وخدمة AI worker منفصلة كما في `infra/docker-compose.yml`; لا رصد خارجي مذكور.
- [ ] التكوينات الحساسة أو المفاتيح التي يجب حمايتها وكيفية إدارتها: ملف الإعداد `config/settings.py` يحتوي قيمًا افتراضية ثابتة لـ `JWT_SECRET` وبيانات S3، وملف `.env` موجود في الجذر (يحتوي بيانات حساسة) — يلزم نقل الأسرار إلى إدارة آمنة وعدم الالتزام بها في المستودع.

## 5. خريطة قاعدة البيانات

- [x] وصف مختصر للمخطط الحالي وعلاقات الجداول الحرجة: وفق `SCHEMA_MIGRATION.md` الجداول الحرجة تشمل `users`, `roles`, `user_roles`, `engagements`, `annual_plans` مع أعمدة camelCase جديدة، بينما الشيفرة ما زالت تستخدم بعض أعمدة snake_case؛ توجد علاقات أساسية عبر مفاتيح userId/roleId وارتباط engagements بخطط سنوية.
- [ ] مشاكل الأداء المعروفة أو الفهارس المطلوبة: لا يوجد سجل بفهارس جديدة؛ الاستعلامات الحالية تعتمد على `SELECT` خام دون فهارس داعمة، ولم يتم توثيق عنق زجاجة محدد.

## 6. سجل المشكلات والانقطاعات

- [x] أبرز الأعطال السابقة أو الثغرات التي يجب تفاديها: مستندات مثل `ADMIN_USER_CREATION_DEBUG.md` و`ADMIN_PAGE_UPDATE_REPORT.md` توثق أخطاء مصادقة متكررة ورسائل Unauthorized؛ كما أن محاولة `docker-compose up -d --build api` تفشل حاليًا (سجل المحطة بتاريخ 31-10-2025).
- [ ] متطلبات الامتثال أو التدقيق (audit/compliance) ذات الصلة: لا توجد متطلبات رسمية مذكورة في المستودع، يلزم التحقق مع الفريق القانوني/الامتثال.

## 7. وثائق وسياسات قائمة

- [ ] روابط أو مسارات للسياسات الداخلية (معايير التسمية، الأمن، مراجعات الكود): لا تتوفر سياسات رسمية؛ يوجد `SCHEMA_MIGRATION.md` و`FRONTEND/README.md` لكن لا توجد إرشادات هندسية موحدة.
- [ ] أي أدلة تشغيل أو إجراءات Incident Response: توجد أدلة تشغيل متفرقة (`ADMIN_USER_SETUP.md`, `ADMIN_USER_CREATION_DEBUG.md`) لكنها خاصة بحالات محددة؛ لا يوجد Runbook شامل أو خطة Incident Response.

## 8. الجداول الزمنية والأولويات

- [ ] مواعيد التسليم أو القيود الزمنية للمشروع: لم تُشارك مواعيد رسمية بعد.
- [ ] أجزاء لا يمكن تغييرها حاليًا أو يجب إنجازها أولًا: لم يحدد الفريق نطاقًا محميًا؛ يفترض الحفاظ على عقود الـAPI الحالية كما ورد في المتطلبات.

## 9. ملاحظات إضافية
